## 4. 渲染质量：已修复（2026-11-27，R2）

旧版导出的 PNG 为 256×256 时仅 **433 字节**、800×600 时仅 **845 字节**，属纯色空白图。原因与现状：

| 旧问题 | 现状（2026-11-27 实测） |
|---|---|
| 图层元数据 `defaultVisibility: false` | ✅ 5 层全部 `true`（FACILITY/DISTRICT/STREET/RESIDENTIAL/ROAD） |
| 图层 `extent` 全 0 | ✅ 均有有效范围（如 FACILITY `114.126963,30.337201,114.51232,30.667363`；ROAD `114.1208608,30.4783982,114.5619213,30.6751661`） |
| `export` 出白图 | ✅ 800×600 导出 **27,067 B**，含区界面、路网、五类设施符号与官方水印；证据 `docs/screenshots/igs-map-export.png` |

**根因与处置**：`data/mapdoc/wh_facility.mapx` 图层状态本身为 `VISIBLE`（STREET 为编辑态 `ACTIVE`，IGServer 同样按可见处理），空白是**旧服务指向旧地图文档副本**所致。2026-11-27 用当前 mapx 经 Manager 重新发布 `wh_facility_main` 后出图正常；原 doc 中“重算图层范围”步骤在当前 mapx 上已无需再做（范围均有效）。

> 复现：`curl -o map.png "http://localhost:6163/igs/rest/services/wh_facility_main/MapServer/export?bbox=114.12,30.33,114.56,30.68&size=800,600&format=png&f=image"` → 文件大小 > 20 KB 即非空白。

> **CLI 登录失败的真实原因**：Manager 前端用 crypto-js 对密码加密后再提交，直接用明文 POST 必然判错。
> **已逆向并验证的登录方式（2026-11-27）**：前端加密为 **AES-128-ECB**，key = ASCII `313233343536373a`，PKCS7 填充，输出 base64；提交 `POST http://localhost:9999/manager/user/login`（form: `username=admin`、`password=<base64>`），返回 `{"msg":"success","code":1,"token":"…"}` 并种下 `IGS_MANAGER_ID` cookie，后续请求带 `X-Token: <token>` 即可调用 `/manager/servicehub/*` 等接口。无需浏览器。

```powershell
$key=[Text.Encoding]::UTF8.GetBytes("313233343536373a")
$aes=[Security.Cryptography.Aes]::Create(); $aes.Mode="ECB"; $aes.Padding="PKCS7"; $aes.Key=$key
$t=[Text.Encoding]::UTF8.GetBytes("sa.mapgis")
$b64=[Convert]::ToBase64String($aes.CreateEncryptor().TransformFinalBlock($t,0,$t.Length))
# POST /manager/user/login  username=admin password=$b64
```
