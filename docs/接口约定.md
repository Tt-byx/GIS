## 1. 这份文档解决什么问题

`03-api-contract.md` 是唯一权威，但它按"接口"组织，前端同学真正需要的是**一张字段名对照表 + 一张错误码表 + 一串坑**。本文把这三样抽出来，并记录 SPEC 未覆盖、由 R7 拍板的边界处理。

**权威优先级（冲突时按此顺序，不许反过来）：**

1. `SPEC/03-api-contract.md`（路径、参数、响应结构）
2. `SPEC/02-data-model.md` §6（字段名映射）
3. `SPEC/05-conventions.md` §4（错误码与 `msg` 原文）
4. `api/openapi.yaml`（上述三者的镜像）
5. 本文（边界澄清与交接约定）

前端 MUST NOT 为了适配后端实现而改字段名（A-18）；后端 MUST 按契约输出。

## 3. 统一响应包装（前端已按此实现）

除 API-07 成功响应（文件流）外，全部响应为此结构：

```json
{ "code": 0, "msg": "success", "data": {}, "traceId": "a1b2c3d4e5f6" }
```

| 规则 | 内容 |
|---|---|
| A-01 | `code != 0` 时 `data` MUST 为 `null`，MUST NOT 返回部分数据 |
| A-02 | `msg` 必为中文、可直接展示；不含 `Exception`、堆栈、SQL |
| A-03 | 成功响应也 MUST 带 `traceId`（12 位十六进制） |
| A-06 | 字段有值域但当前无值 → 返回 `null` 并**保留键**；字段不适用 → 省略键 |
| A-23 | MUST NOT 用 `0` 代替 `null` |

**前端现状**：`frontend/src/api/http.js` 已经实现"`code===0` 取 `data`、非 0 抛 `ApiError(code, msg, traceId)`、无 `code` 字段则原样透传（文件流）"。所以后端只要严格输出上述结构，`api/*.js` 不需要改一行。

## 4. 分页（仅 API-02）

请求：`page`（≥1，默认 1）、`size`（1–200，默认 20）。

响应 `data` 固定为：

```json
{ "total": 0, "page": 1, "size": 20, "list": [] }
```

- `total` MUST 是**满足条件的总数**，不是当前页条数（A-07）。
- `list` 为空 MUST 返回 `[]`，MUST NOT 返回 `null`。

## 6. 错误码（`msg` 必须逐字一致）

| code | HTTP | msg | 典型触发 |
|---|---|---|---|
| `0` | 200 | `success` | 成功 |
| `1001` | 400 | `参数校验失败` | 必填缺失、`kw` 过短、`type` 非枚举 |
| `1002` | 400 | `参数超出允许范围` | `size > 200`、枚举非法、阈值非 5/10/15 |
| `2001` | 404 | `数据不存在` | 统计无数据、`categoryL2` 不存在 |
| `2002` | 422 | `数据未就绪` | OD 矩阵缺失、网络数据集未发布 |
| `3001` | 503 | `地图服务连接失败，请检查 IGServer 是否启动` | IGServer 不可达 |
| `3002` | 502 | `地图服务返回错误` | IGServer 返回非 0 |
| `4001` | 504 | `计算超时，建议缩小范围` | 分析超时 |
| `5000` | 500 | `系统异常` | 未捕获异常 |
| `5001` | 429 | `今日查询额度已用尽` | 高德配额超限 |

后端 MUST 用 `ErrorCode` 枚举（C-33，不许写数字字面量）；前端 MUST 按 `code` 分支（C-34，不许匹配 `msg` 文本）。

## 7. 七条最容易写错的边界

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 以为 `/facilities` 支持矩形范围 | **契约参数表里没有 `bbox`**。画框查走前端直连 IGServer（A-20）。加参数 = 违反 A-04 |
| 2 | 把 `CAT_L1` 全删了 | 禁的是**原始列名**，`categoryL1` 必须返回。验收 grep 用 `grep -i '"CAT_L1"'`，不要 `grep CAT_L1` |
| 3 | 给 xlsx 也加 BOM | xlsx 是 zip（开头 `PK`），加 BOM 直接损坏文件。**只有 csv 加 `EF BB BF`** |
| 4 | `breaks` 硬编码 5 等分 | 必须用分位数，且长度 6、严格递增、首=min、末=max。见 §9-① |
| 5 | `value` 算不出时填 0 | 填 `null`。前端已按 `null` 渲染 `—` |
| 6 | `keyword` 直接拼进 LIKE | `%` `_` `\` 必须转义，否则 `%` 能查出全表 |
| 7 | `status` 默认值漏了 | 默认 `正常`；`status=ALL` 时**不加**状态条件（不是 `AND STATUS != ''`） |

另外两条易忽略：`total` 是总数不是页数；`list` 空必须 `[]`。

## 9. 契约未覆盖、由 R7 拍板的四处边界

> 四处都已在 `api/openapi.yaml` 里落成可读定义，并在代码注释中标注来源。其中 ①④ 建议补一次 SPEC 澄清（`T-900` 或组内纪要），②③ 按本文执行即可。

**① `breaks` 在"所有 score 相同"时数学上无解。**
契约要求长度 6、严格递增、首=min、末=max；若 `max == min`（例如全为 0），三者不可能同时满足。处理：`breaks` 仍返回 6 个元素（首末为 `min`/`max`），但**退化为非严格递增**，全部 `score` 落 `level = 3`，并在响应 `stats` 后附加说明。这不是取巧——5 级分类在零方差数据上没有意义，硬造递增断点是伪造数据。

**② BOM 只给 csv，不给 xlsx。**
`03 §9` 规则 1 写"文件 MUST 为 UTF-8 with BOM（前 3 字节 `EF BB BF`）"，对 xlsx 不成立（zip 容器）。执行口径：csv 加 BOM（否则 Excel 中文乱码），xlsx 不加。`X-Row-Count` 与 14 位时间戳两种格式都要。

**③ `capacityFallback` 的落点。**
`03 §8` 规则 6 要求"S 为 null 或 0 时用 1 代替并在 `stats` 后附加说明 `capacityFallback: true`"，但响应字段表里没有这个键。落在 `data.stats.capacityFallback`（boolean，始终返回），已在 openapi 定义。

**④ 导出类型的 `params` 结构。**
契约只写"对应查询的筛选条件"，未定义 schema。执行口径：`type=STAT_DISTRICT` 时 `params` 与 API-04 的查询参数同名同值（`level`/`categoryL1`/`metric`）；`type=COVERAGE` 时用 `taskId`；`type=ANALYSIS` 时用 `taskId`。前端 R5 按此传参，后端按此取数。
